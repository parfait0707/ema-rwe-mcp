- `catalogue_status` に本体版、DB版、辞書版、更新成功・失敗を表示する。

**3．公開・更新方法：短期はPyPI、中長期はリモートMCPを推奨します。**

| 方法 | 導入の容易さ | 最新版への追従 | このプロジェクトへの適合 |
|---|---|---|---|
| GitHub＋uvx | uv・git・設定が必要 | 固定タグは更新されない | 開発者・再現用 |
| PyPI＋uvx | git不要、ソースビルド不要 | 起動時の最新版指定が可能 | **短期の第一候補** |
| Claude Desktop用 `.mcpb` | GUIで導入できる | 配布経路の更新運用が必要 | Claude初心者向け |
| リモートMCP | URL登録で利用できる | 提供側で更新を反映できる | **中長期の第一候補** |

PyPIでは、公開後の起動設定を例えば `uvx --from ema-rwe-mcp@latest ema-rwe-mcp` にできます。通常のuvxはキャッシュした版を再利用するため、**版指定を外すだけでは最新版の利用を保証できません**。`@latest` は最新版確認とキャッシュ更新を行います。ただし、起動済みプロセスの更新には再起動が必要です。[uv公式文書](https://docs.astral.sh/uv/concepts/tools/)

Claude Desktop向けには、ワンクリック導入の `.mcpb` が有力です。Python・uv方式も仕様にあります。対応クライアント版と、PyMuPDFを含むWindows/macOSでの動作確認が必要です。[Anthropic公式解説](https://www.anthropic.com/engineering/desktop-extensions)、[MCPB仕様](https://github.com/modelcontextprotocol/mcpb/blob/main/MANIFEST.md)

MCP Registryへの掲載も有用ですが、これは発見・配布先案内の仕組みです。登録だけでホスティングや全クライアントの自動更新が実現するわけではありません。[Registry公式説明](https://blog.modelcontextprotocol.io/posts/2025-09-08-mcp-registry-preview/)

「初心者が簡単に導入し、常に提供側の最新安定版を使う」を最も満たしやすいのはリモートMCPです。CodexはURL接続のStreamable HTTPをサポートします。ただし現在の実装はstdio専用なので、HTTP対応に加え、利用者ごとの解析・比較の分離、共有キャッシュ、全利用者を通じたEMAアクセス制限、成果物のダウンロード方法が必要です。[Codex公式仕様](https://learn.chatgpt.com/docs/extend/mcp?surface=cli)

月次DB更新については、**コードとデータを別々に版管理する構成**を推奨します。

1. 保守者が月次CSVを取得し、全研究と種別CSVの整合性を検証する。
2. DBを再構築・検証・VACUUMし、日付とSHA-256を持つ不変のスナップショットとして公開する。
3. 利用者側は起動時に小さな更新情報を確認し、変更時だけDBを取得する。
4. 検証後にカタログ部分を更新し、利用者の解析・回答・PDFは保持する。
5. 更新失敗時は旧版で動作し、状態に失敗を明示する。

これなら、利用者に毎月EMAのCSV exportを行わせずに更新できます。現在の「新しい同梱DBでカタログだけを差し替える」実装は、この構成の土台になります。

公開の進め方としては、まず **PyPI配布とタグ起点の自動リリース**、次に **月次DBの独立配信**、初心者向けの **`.mcpb`**、利用者が増えた段階で **リモートMCP** が現実的です。PyPI公開はGitHub ActionsとTrusted Publishingで自動化できます。[PyPA公式手順](https://packaging.python.org/en/latest/guides/publishing-package-distribution-releases-using-github-actions-ci-cd-workflows/)

研究の再現性のため、最新安定版を既定にしつつ、各比較結果には本体・DB・parserの版とPDFハッシュを記録し、過去版を指定する経路も残すことを勧めます。
