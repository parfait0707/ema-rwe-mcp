# コード表の位置の行（spec v1.33 案）と計画

- 作成：2026-11-23（JST）。対象は main `86de6ae`（v0.6.0 ＋ spec v1.32）。
- 所有者の決定：証拠テーブルに位置の行を足す。全部ではなく、コード表だけを位置の行にする。研究をまたいでコードで探す問いは、現時点では要らない。抽出ロジックは案 C（選択・除外基準の行に定義とコードを持たせる）。
- 根拠：ポインタの試験（`docs/agent_report/202611231700_opus_pointer-trial.md`、Git 管理外）。経路 P の誤りは、位置の情報の作り方（文中のコード、数字の無い用語の表、10 ページの上限、表の連続）と文字の層に由来した。

## 1. データの形

位置の行は、事実の行と同じ `find_facts` の行として返す。項目種別は `code_table`。

| 項目 | 中身 |
|---|---|
| `value` | 表の見出し。しおりの階層（`chapter_path`）をそのまま使う（例「17.4.1.2 Hypertension / 17.4.1.2.1 ICD-10-CM Codes」） |
| `page`、`end_page` | 表の最初と最後の物理ページ。ページ数に上限を置かない |
| `section_id` | 最初の節 |
| `kind` | `codes`（コードが並ぶ）または `terms`（MedDRA など数字のコードが無い用語の一覧） |
| `evidence` | 見出しの行 1 行の逐語引用。今の照合の仕組みで、行が本当にそのページを指していることを確かめられる |
| `status` | 手元の PDF から作るので `verified_local` |

| `systems` | そのページの範囲に出るコード体系の目印（`ICD-10`、`ICD-9`、`ICD-11`、`ATC`、`MedDRA`、`CPT/HCPCS`、`NDC`、`OPCS-4`、`Read`、`SNOMED CT` など）。見出しの語を優先し、見出しに無ければコードの形から推す。事実ではなく目印で、呼出元はページを読んでから体系を確かめる |

LLM は使わない。PDF の解析結果（節、しおり、`lists_codes`）だけで作る。コード体系は、体系ごとの判定の表（見出しの語とコードの形）で持ち、ICD-11 のような新しい体系は表に 1 行足して扱う。形だけでは紛れる体系（ICD-10 と OPCS-4、3 桁の ICD-9 と他の数字）は、見出しの語が無ければ目印を付けないか「形からの推定」と示す。

### 章の地図（`section_map`）

コード表以外の項目の場所も、同じく LLM を使わずに持つ。項目種別は `section_map`。

| 項目 | 中身 |
|---|---|
| `value` | 章の見出し（`chapter_path`） |
| `role` | 解析が判定した章の役割（`population`、`definitions`、`methods`、`data_sources`、`analysis`、`objectives`、`appendix`、`amendments`、`conduct`、`abstract`） |
| `page`、`end_page` | 章の最初と最後の物理ページ |
| `evidence` | 見出しの行 1 行の逐語引用 |

役割は見出しの語から判定しているので、外れることがある。中身の正しさは保証せず、「どこを読めばよいか」の目印として使う。参考文献、目次、管理、チェックリストの章は入れない。事実の行は、今までどおり 1 件ごとにページと引用を持つ。

## 2. 作り方

1. 節ごとに、コード表か（`lists_codes`）、用語の一覧か（付録で、題に MedDRA、preferred term、terms、code list などを含む）を判定する。
2. 同じ見出しの下で続くページを 1 行にまとめる。ページ数の上限は置かない。
3. 本文の章にあるコード表も、付録と同じように行にする。

## 3. いつ作り、どこに持つか

- プロトコルを手元に保存したとき（`get_protocol`、`prefetch-protocols`）に作り、`protocol_observations` に `code_tables` として保存する（`protocol_id` と組にする）。`text_layer` と同じ置き場所である。
- v1.33 より前に保存した PDF（claims の 560 研究）は、`find_facts` が初めてその研究を読むときに作って保存する。解析は 1 研究あたり 1〜6 秒（試験の実測）。
- 研究をまたいで検索するための索引は作らない（所有者の決定）。

## 4. 抽出の指示の変更

- 位置の行になるコード表は、書き写さない。`disease_definitions` には条件と定義の論理（例「主診断の入院 2 回」）を書き、引用は表の見出しまたは本文の定義の行にする。
- 選択・除外基準や本文の定義の文に書かれたコードは、今までどおり値に書く（案 C の手順 6）。
- 最初のバッチの応答は、`code_pages` の代わりに `code_tables`（位置の行の一覧）を返す。
- spec v1.32 の「未引用のコード表のページ」の注記は、位置の行が覆うページを数えない。
- claims の抽出済みの事実は消さない。抽出し直しもしない。

## 5. 呼出元の手順（`docs/mcp-workflow.md`）

コードを問われたら：
1. `find_facts(study_ids=[...], item_kinds=["code_table"])` で位置の行を取る。
2. 問いの概念に合う行を見出しで選ぶ。行が長ければ `search_protocol_text` で概念の語の出るページに絞る。
3. `read_protocol_text(start_page, end_page)` で読み、1 コード 1 引用で答える。
4. 答えは `cache_protocol_answer` で保存する（次からは読まずに返せる）。

事実の行に同じコードがあれば（claims）、事実の行で答えてよい。1 コードごとの引用が要るときだけページを読む。

## 6. 計画

| 段 | 中身 | 確かめ方 |
|---|---|---|
| P1 | 位置の行と章の地図を作る関数（`pdf.py`）、コード体系の判定の表、その単体テスト | 試験の 10 問の PDF で、正解の表が行に入ること。体系の目印が見出しと合うこと |
| P2 | 観測への保存と、`find_facts` の `code_table` 行 | CLI `facts --item-kind code_table` と MCP の parity テスト |
| P3 | 抽出の指示と `code_tables` の応答、v1.32 の注記の調整 | 既存のテストと正解データの確認 |
| P4 | spec v1.33、手順書、AGENTS.md、検証記録 | `scripts/check.py` |
| P5 | 再試験：同じ 10 問を、位置の行を使う経路 P で答えさせる | 合格の基準は、完全正答 9/10 以上、再現率 99% 以上（経路 F と同じ水準） |

P5 に合格したら、ehr と registry の事前取得と抽出に進む。合格しなければ、失敗の形を見て P1 に戻る。

## 7. 入れないもの

- 研究をまたいでコードで探す索引
- 位置の行を配布する事実（`prebuilt_facts`）に含めること（PDF を持たない利用者向け）。必要になったら別の版で扱う
- 文中に 1 つだけ書かれたコード（例：除外基準の N18.5）の位置の行。これは案 C の事実の行で扱う
