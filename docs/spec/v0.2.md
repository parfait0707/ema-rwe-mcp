# v0.2 追加要件

ユーザーの2026-09-12の追加要望により、v0.1の次の部分を更新する。

1. 研究検索とPDF内検索に同義語展開を導入し、利用した展開をJSONに記録する。呼出元から追加同義語を渡せ、内部LLMにも検索式を提案させられる。
2. PDFの章番号・親章・前後関係・付録境界を考慮し、目次や背景、参考文献、ENCePPチェックリストを研究方法と混同しにくくする。章番号だけで意味を固定しない。
3. LiteLLMを任意依存として追加。Gemini、Anthropic、OpenAI、Azure OpenAI、Amazon Bedrockに接続する設定を提供する。既定の呼出元LLM方式は引き続きAPIキー不要。
4. 取得したプロトコルPDFはID付きでローカルに保持する。**この要望はv0.1のPDF一時保存方針を更新する**。HTTPキャッシュはTTLを維持するが、PDFアーカイブはユーザーが削除するまで残す。旧版も保存し、本文の差し替えはSHA256で区別する。
5. IDを指定して全章一覧、全文検索、ページ読取り、質問別の探索・回答保存を行える。ローカル探索はEMA接続不要。最新性確認とは分離する。
6. 内部LLMの自律探索は対象PDFの検索／章一覧／読取りに限定し、ステップ数を制限する。質問別回答は従来の共通抽出とは別保存し、引用照合後に再利用する。

MCPは12 Tool。利用方法・設定・制約は [追加探索ガイド](../exploration.md) を参照。通常の研究検索は引き続きローカルFTS/BM25を使用し、全PDFの一括取得や全文vector DBは導入しない。

## 2026-09-13の追加要件

現行の抽出schemaは0.2、MCPは17 tools。Data Sources CSVを必須にせず、PDFの質問別探索でデータタイプと定義用途を判定し、希望タイプを優先する。PDF一次判定上限と比較表示上限は独立設定（既定は各5件）。詳細は[用途別分類](../source-types.md)と[比較](../comparisons.md)を参照。旧解析は履歴へ保全して再抽出する。
