# v1.20 追加要件：抽出の正解データによる検査、節の続きのページ

2026-11-20。v1.19 に加える。
抽出の精度を、手で読んだ正解と照らして確かめる仕組みを、リポジトリに置く。スクリプトを変えるたび（push の前）と、月ごとのカタログのスナップショットを作るたびに、同じ正解で確かめる。実測は[検証記録](../validation.md) の 2026-11-20 の節、使い方は [tests/fixtures/extraction_gold/README.md](../../tests/fixtures/extraction_gold/README.md)。

1. **正解データ**：`tests/fixtures/extraction_gold/eligibility.json`。4 つのプロトコル（研究 49324、49276、49285、105807）の組入れ基準と除外基準の全項目（51 項目）を、人が読んで列挙したもの。項目ごとに、自分の言葉での説明（`label`）、物理ページ（`page`）、その箇所を利用者の手元の PDF から見つける短いパターン（`pattern`）、抽出結果の採点で受け入れる鍵となる語（`accept`。読み手が別の言い方や別の行で書きうる項目）を持つ。プロトコルごとに、文書の URL、版、SHA-256、ページ数を持つ。**プロトコルの本文は持たない**（PDF もその引用もコミットしない。引用は、検査のたびに利用者の手元の PDF から取る）。
2. **サーバーの判定の検査（LLM もネットワークも使わない）**：`scripts/extraction_eval.py check`。正解の全項目について、次を確かめる。1 つでも外れたら失敗とする。
   - その箇所が、正解のページで見つかる（PDF の parser）。
   - `analyze_protocol` が読み手に渡す範囲にある（背景、参考文献、目次、チェックリストに分類されていない）。
   - `research_protocol` が、正解の質問で返す範囲（既定の文字数の上限内）に入っている。
   - その箇所の引用が、根拠として受理される。1 ページずれた引用が、正しいページへ直される。
   - PDF のページ数が、正解と同じである。
   手元に無いプロトコルは、その旨を表示して飛ばす。`--require` では失敗とする。
3. **push の前**：`scripts/check.py` に `gold` の段階を加える（`tests` の後）。`extraction_eval.py check --require` を実行する。正解のプロトコルは、clone ごとに 1 回 `extraction_eval.py fetch` で取得する（EMA から、1 件ずつ間隔を空けて。取得は作業用の複製の DB で行い、同梱の DB を書き換えない）。取得していない clone では、`check.py --allow-missing-gold` で、手元にある分だけを確かめる。
4. **月ごとのスナップショット**：`scripts/build_catalogue_snapshot.py` は、スナップショットを書き出した後、その DB の複製に対して `extraction_eval.py catalogue`（正解の研究が、新しいカタログに Non-interventional study として載っている）と `check --require` を実行する。失敗したら終了コード 1 で終わり、公開しないよう表示する（書き出したファイルは残し、内容もハッシュも変えない）。`--skip-gold` で省ける。標準出力は、これまでどおり manifest だけとする。
5. **正解の文書が最新かの確認**：`extraction_eval.py catalogue --online` は、研究ごとに Study documents を 1 回ずつ（間隔を空けて）取得し、最新のプロトコルが正解の文書のままかを確かめる。変わっていたら、正解を読み直して改める。月ごとの手順で 1 回実行する。DB の複製で行う。
6. **読み手の抽出の採点**：`extraction_eval.py grade` は、DB に保存済みの、正解の質問への質問別回答と、解析の `cohort`（組入れ基準、除外基準）を採点する。項目ごとに、回答にあるか（`answer_found`）、その回答の引用自体にあるか（`answer_supported`）、`cohort` にあるか（`cohort_found`）。プロトコルごとに、正解の `minimum`（回答 0.9、`cohort` 0.7）を下回れば失敗とする。`extraction_eval.py run` は、設定済みの内部 LLM で抽出と質問別回答を行ってから採点する。呼出元抽出（既定）の採点は、呼出元が正解の質問で `analyze_protocol` を済ませた後に `grade` を実行する。採点は LLM の呼び出しを伴うので、push の前の検査には含めない。月ごとの手順とアプリのリリースの手順で行う。
7. **節の続きのページを、検索の結果に含める**：`search_protocol_text` と `research_protocol` は、ヒットした節が次（または前）のページへ続くとき、続きのページ（同じ見出しで、ページが連続するもの。前後それぞれ 3 ページまで）を、ヒットの直後（直前）に加えて返す。続きのページは、`continues` にヒットの `section_id` を持ち、`matched_terms` は空で、`limit` には数えない。文字数の上限は、これまでどおり全体に掛かる。正解データの検査で見つかった欠落（研究 49324 の除外基準の後半が、検索語を含まない次のページにあり、質問への回答に使う範囲から漏れていた）への対応。`analyze_protocol` の読む範囲、fingerprint、抽出の指示は変えない。
8. **対象の範囲**：組入れ基準と除外基準だけ、英語で文字層のある 4 つのプロトコルだけ。データソース、アウトカム、コードリストは採点しない。`accept` の語は緩い（年齢の基準は「18 years」だけで受け入れる）ので、採点は「その基準に触れているか」を見るもので、内容の正しさの保証ではない。
