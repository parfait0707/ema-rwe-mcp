# EMA RWE MCP Server 開発仕様書

- Document Version: 0.1
- Status: Draft / MVP Specification
- Target: HMA-EMA Catalogues of real-world data sources and studies
- Primary Scope: DARWIN EU Study / Study Protocol 検索・取得・解析

# 1. 背景

HMA-EMA Catalogues of real-world data sources and studies には、DARWIN EUを含むReal-World Evidence（RWE）研究のStudy metadata、Study protocol、Final report等が公開されている。

本システムでは、ユーザーが自然言語で提示した研究条件に対して、EMA Catalogue内から類似研究を検索し、必要に応じてStudy Protocol PDFを取得・解析して、研究デザイン等の情報を構造化して返却するMCP Serverを構築する。

対象サイト:

https://catalogues.ema.europa.eu/

DARWIN EU Study検索例:

https://catalogues.ema.europa.eu/search?f%5B0%5D=content_type%3Adarwin_study

---

# 2. 基本方針

本システムでは、以下の原則を採用する。

1. EMAサイト全体を無差別にクロールしない。
2. Study metadataの母集団には、EMAが正式に提供するCSV Exportを優先して利用する。
3. Study検索は原則としてローカルIndexに対して実施する。
4. Study detail pageおよびProtocol PDFは、必要なStudyについてのみオンデマンド取得する。
5. EMAへのHTTPアクセスにはRate Limit・Retry・Cacheを設ける。
6. Protocol PDFの恒久保存を前提としない。
7. PDF全文・抽出全文を恒久的な検索DBとして再配布しない。
8. PDFから生成した構造化情報については、必ず出典情報を保持する。
9. CoreロジックはMCPに依存させない。
10. MCP ServerはCore Python LibraryをLLM/Agentから呼び出すためのadapterとして実装する。
11. PDF抽出schemaはMVPで固定しすぎず、実Protocolを評価しながら段階的に拡張する。
12. Computer-Using Agent / Browser AutomationはMVPには導入しない。

---

# 3. システムの目的

## 3.1 MVPの目的

ユーザーが以下のような自然言語の研究条件を入力した場合、

> DOACの安全性をactive comparator cohort designで評価し、propensity scoreを利用しているDARWIN EU研究を探して

以下の処理を実行できることをMVPの完成条件とする。

1. EMA Study metadataから候補Studyを検索
2. 条件との関連性が高いStudyをランキング
3. Studyの基本情報を取得
4. Study Documentsから最新Protocolを特定
5. Protocol PDFをオンデマンド取得
6. PDFをText/Markdownへ変換
7. Study design等の最低限の情報をLLMで構造化
8. Protocolのpage / section / URL等の出典を付けて返却

---

- EMA Catalogue全ページの定期クロール
- 全Protocol PDFの一括ダウンロード

- 疾患・薬剤コード体系の自動正規化
- OMOP Concept ID Mapping
- LLMによる完全自律ブラウザ操作
- Computer-Using Agent
- Selenium / PlaywrightによるGUI操作
- Final Study Reportの詳細解析
- Study間の自動Meta-analysis
- 論文検索との統合
- PubMed等との自動リンク
- 自動研究計画書生成

これらはMVP評価後にPhase 2以降で検討する。

# 7. レイヤー構成

本システムは以下の4層に分離する。

## Layer 1: Core Domain

MCP、HTTP、SQLite等に依存しないデータモデル・business logic。

例:

- Study
- StudyDocument
- Protocol
- StudySearchQuery
- ProtocolAnalysis

---

## Layer 2: Infrastructure

外部システムアクセスを担当。

- EMA HTTP Client
- CSV Importer
- SQLite Repository
- PDF Downloader
- PDF Parser
- Cache
- LLM Client

---

## Layer 3: Application Service

ユースケース単位の処理。

例:

- SearchStudiesService
- GetStudyService
- GetProtocolService
- AnalyzeProtocolService

---

## Layer 4: MCP Adapter

MCP Toolを公開する。

MCP Tool内部には複雑なbusiness logicを書かない。

Bad:

```python
@mcp.tool()
async def search_studies(...):
    # CSV読み込み
    # SQLite
    # EMAアクセス
    # Ranking
    # PDF解析
    ...
```

Good:

```python
@mcp.tool()
async def search_studies(query: str, limit: int = 10):
    return search_service.execute(
        query=query,
        limit=limit,
    )
```

# 14. LLM Reranking

MVPではOptionalとする。

検索結果の品質がFTSのみで十分なら利用しなくてもよい。

Rerankingでは以下を考慮する。

- Population similarity
- Exposure similarity
- Comparator similarity
- Outcome similarity
- Study design similarity
- Analysis similarity

研究デザインの類似性は、単なる疾患・薬剤一致より高く評価できるようにする。

ただし重みはMVP評価後に調整する。

# 23. PDF Page情報

Page numberを失わないこと。

内部表現例:

```python
@dataclass
class PDFPage:
    page_number: int
    text: str
```

section parser後も、

```python
@dataclass
class ProtocolSection:
    heading: str
    section_number: str | None
    start_page: int
    end_page: int
    text: str
```

のようにpage情報を保持する。

---

# 24. Section Parser

DARWIN Protocolで頻出する以下のSectionを優先的に認識する。

```text
RATIONALE AND BACKGROUND

RESEARCH QUESTION AND OBJECTIVES

RESEARCH METHODS

Study Type and Study Design

Study Setting and Data Sources

Study Period

Follow-up

Study Population

Variables

Study Size

Analysis

Evidence Synthesis

LIMITATIONS
```

ただし固定されたSection番号に依存しすぎない。

例:

Bad:

```python
if heading == "8.5":
    population = ...
```

Good:

```text
section number + heading text
```

の両方から判定する。

---

# 25. LLM Protocol Extraction

LLMにはPDF全文を無条件に渡さない。

原則:

```text
Section Parser
      ↓
Relevant Sections
      ↓
LLM
```

とする。

例えばStudy Design抽出には、

```text
Research Question
Study Type and Study Design
Study Population
Analysis
```

等のSectionを利用する。

---

# 26. Hallucination対策

LLM Promptでは以下を強制する。

1. Protocolに明示されていない内容を事実として補完しない。
2. 判断不能の場合はnullを返す。
3. inferenceとexplicit statementを区別する。
4. 出典page/sectionを返す。
5. Protocol記載と自身の方法論的評価を混在させない。

例:

```json
{
  "value": null,
  "reason": "Not explicitly stated in the protocol"
}
```

を許容する。

# 32. Rate Limiting

MVP初期値:

```text
max concurrency = 1

minimum interval = 2 sec
```

---

# 33. 429対応

HTTP 429を受信した場合:

1. Retry-After確認
2. 指示された時間待機
3. exponential backoff
4. retry上限後はエラー返却

無限retryは禁止。

---

# 34. Retry Policy

対象:

```text
408
429
500
502
503
504
```

例:

```text
max retries = 3

backoff:
2s
5s
15s
```

Retry-Afterがある場合はそちらを優先する。

# 37. Copyright / Secondary Use Policy

MCP Serverは以下の方針とする。

## Metadata

公式ExportされたStudy metadataはローカルIndexとして利用する。

---

## Protocol PDF

必要なProtocolのみオンデマンド取得する。

全Protocolを無差別に永久保存しない。

---

## Protocol Text

全文を外部へ再配布することを主目的としない。

解析後のraw textはtemporary cache扱いとする。

---

## Structured Result

研究デザイン等の構造化抽出結果は保存可能とする。

---

## Citation

Structured resultには可能な限り以下を保持する。

```text
Study ID
Study URL
Protocol URL
Protocol Version
Page
Section
Accessed At
```

# 51. 設計上の重要原則

## 51.1 MCPをシステム本体にしない

本体:

```text
EMA RWE Core Python Library
```

公開interface:

```text
MCP
```

とする。

---

## 51.2 検索とProtocol解析を分離する

検索時にProtocol PDFを取得しない。

```text
Metadata Search
        ↓
Candidate Selection
        ↓
Protocol Retrieval
```

とする。

---

## 51.3 LLMに決定論的処理を任せない

以下はPythonで処理する。

```text
CSV parsing

HTTP

Rate limit

Caching

Protocol version selection

PDF page extraction

database access
```

LLMは主に、

```text
semantic reranking

Protocol semantic extraction
```

に利用する。

---

## 51.4 Extraction schemaを早期に固定しすぎない

MVPでは最小限とし、

```text
10〜20 Protocol
```

の評価後にschema v0.2を設計する。

---

## 51.5 Provenanceを最初から設計する

後からcitationを付け足さない。

すべてのStructured Dataについて、

```text
どのStudy

どのProtocol Version

どのPage

どのSection

いつ取得したか
```

を追跡可能にする。

# 53. 設計判断まとめ

MVPでは以下を正式方針とする。

| 項目 | 採用 |
|---|---|
| Metadata取得 | EMA Official CSV Export |
| Metadata保存 | SQLite |
| Search | FTS5 / BM25 |
| Semantic reranking | Optional LLM |
| Study詳細 | On-demand HTTP |
| Protocol取得 | On-demand HTTP |
| PDF保存 | Temporary Cache |
| PDF解析 | PyMuPDF系 |
| PDF chunking | Heading / Section based |
| Protocol抽出 | LLM Structured Output |
| Evidence | Page + Section + URL |
| MCP | Thin Adapter |
| Core | Independent Python Library |
| Browser Automation | MVP対象外 |
| Computer Use | MVP対象外 |
| Vector DB | MVP対象外 |
| Protocol schema | Minimal / Versioned |
| 全PDFクロール | 実施しない |
