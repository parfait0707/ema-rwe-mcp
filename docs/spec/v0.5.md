# v0.5 追加要件：一致語の出所と類縁概念フォールバック

2026-09-26 の要求適合調査（`docs/work_log/20260926230945_requirements_gap_analysis.md`）で、要求 3「ユーザーが求める情報がない場合に、臨床的に類縁の疾患・コホート・アウトカムでの定義を、類縁であると明示して提示する」が未実装と判明した。調査の過程で、検索が依頼概念そのものと別概念の研究を区別せずに返していることも分かった。本版で v0.4 の次の部分を更新する。

1. **辞書の分割**。`data/terminology.json` に `analogous_terms: [{term, relation}]` を新設する。依頼概念とは異なる臨床概念がここに入り、`relation` は `broader`（上位概念）、`sibling`（同じ上位概念に属する別疾患）、`associated`（合併症・関連病態）のいずれかとする。`related_terms` には同義語・表記揺れ・下位型・薬剤／検査の検索ヒントだけを残す。既存 21 概念の語を移した（例：1型糖尿病の diabetes mellitus → broader、心房細動の atrial flutter → sibling、骨粗鬆症の fracture → associated）。関連語導出スクリプトの `--apply` は、`analogous_terms` にある語を `related_terms` へ戻さない。（**v0.6 で変更**：分割後の辞書は既定で読み込まない記入例 `data/terminology.example.json` になった。類縁概念は既定では呼出元が ICD-10 の指針で生成し、`analogous_terms` 引数で渡す）
2. **広義語グループの抑止**。`vocabulary.GROUPS` の広義の臨床語（diabetes、bleeding、cancer）は、辞書概念の入力語が既に覆っている文字列では発火しない。「1型糖尿病」に含まれる「糖尿病」が diabetes を追加し、糖尿病全般の研究を依頼概念として返していた不具合を直す。「糖尿病」単独の質問では従来どおり発火する。（**v0.6 で変更**：辞書がない既定ではこの抑止が効かないため、広義の臨床語グループ自体を削除した。抑止の仕組みは利用者辞書と研究デザイン語のために残る）
3. **一致語の出所**。`search_studies` の結果行と `compare_protocols` の候補に `match_basis`（`concept` / `analogous`）と `matched_terms`（実際に一致した展開語）を付ける。`compare_protocols` の行は `match: {basis, terms}` として比較 JSON に残し、比較表の先頭に「一致の根拠」行を置く。類縁概念での一致は「類縁概念での一致（依頼された概念そのものではない）: 語（relation）」と表示する。
4. **フォールバック**。`match_scope=concept`（既定）で候補が 0 件のとき、応答に `analogous_fallback` を自動で付ける。中身は類縁語とその `relation`・語ごとの研究数、候補件数、上限以内なら候補一覧、呼出元への指示である。PDF は取得しない。依頼概念の研究が索引にはあるのに `role` 以外の絞り込み（`filters` の国・種別・デザイン、`darwin_only`、`status`、`analyzed_only`）で 0 件になった場合は `status=concept_filtered_out` と `concept_index_matches_before_filters` を返し、類縁概念より先に絞り込みの緩和を提案させる。類縁語が未知なら `status=no_analogous_terms` を返し、呼出元に類縁概念の提案を求める。フォールバックの候補は呼出元の `status`・`analyzed_only` も適用する。
5. **類縁概念での検索**。`search_studies` と `compare_protocols` に `match_scope`（`concept` / `analogous`）と `analogous_terms`（呼出元提案の `{term, relation}`、辞書外の疾患向け）を追加する。`match_scope=analogous` は類縁語だけで検索し、依頼概念でも一致する研究は除く（全クエリ変種の概念一致の和集合で除外する）。類縁語は大小文字を無視して重複を除き、最初の表記を残す。CLI の `search`／`compare` にも `--match-scope` と `--analogous TERM:RELATION` を追加する。応答の `analogous_terms` と `analogous_note` で、全候補が類縁概念での一致であることを示す。
6. `plan_study_search` は辞書の `analogous_terms` を返す。`use_llm=true` のときは LLM にも類縁概念（最大 10 件、relation 付き）を提案させ、スキーマを検証する。
7. PDF に目的の定義がなかった場合の自動検出は行わない。呼出元は回答が欠けていたとき、`match_scope=analogous` での再検索を利用者に提案する（`docs/mcp-workflow.md`）。

見送り（ユーザー判断）：比較表へのアウトカム・曝露・比較対照・解析手法の列追加（質問への回答で足りる）、抽出結果の共有キャッシュ配布、質問・回答・解釈の triplet による質問回答キャッシュ（今後の課題）。
