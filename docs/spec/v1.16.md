# v1.16 追加要件：MCP ツールの注釈と進捗通知

2026-11-20。v1.15 に加える。
根拠は、18 のツールが、何を変えるか・外部に通信するかの手がかりなしに並んでいたことと、時間のかかる呼び出しの途中経過がクライアントに伝わらなかったこと（[検証記録](../validation.md) の 2026-11-20 の節）。

1. **全ツールに題名と注釈を付ける**：`title` と、MCP の 4 つのヒント（`readOnlyHint`、`destructiveHint`、`idempotentHint`、`openWorldHint`）を全 18 ツールに付ける。クライアントは、確認を求める呼び出しの判断に使える。ヒントは次の意味で付ける。
   - `readOnlyHint`：利用者が保持するもの（カタログ、PDF、解析、回答、比較の出力）を変えない。
   - `destructiveHint`：保存してあるものを、写しを残さずに置き換えることがある。
   - `idempotentHint`：同じ呼び出しを繰り返しても、それ以上は変わらない。
   - `openWorldHint`：EMA か、設定した LLM に通信することがある。
2. **ヒントの割り当て**：

   | ツール | 読み取り専用 | 破壊的 | 冪等 | 外部通信 |
   |---|---|---|---|---|
   | `catalogue_status`、`search_studies`、`list_local_protocols`、`get_protocol_outline`、`search_protocol_text`、`read_protocol_text` | はい | いいえ | はい | いいえ |
   | `plan_study_search` | はい | いいえ | はい | はい（`use_llm=true` のとき） |
   | `get_study`、`get_protocol` | いいえ | いいえ | はい | はい |
   | `compare_protocols`、`analyze_protocol` | いいえ | いいえ | いいえ | はい |
   | `get_protocol_comparison`、`cache_heading_translations` | いいえ | いいえ | はい | いいえ |
   | `cache_protocol_analysis` | いいえ | いいえ | はい | はい（研究ページの確認） |
   | `research_protocol` | いいえ | はい（`force=true` で保存済みの回答を置き換える） | いいえ | はい |
   | `cache_protocol_answer` | いいえ | はい（同じ質問の回答を置き換える） | はい | いいえ |
   | `import_catalogue_csv` | いいえ | はい（取り込んだ研究の行を置き換える） | はい | いいえ |
   | `refresh_drug_dictionary` | いいえ | はい（辞書のキャッシュを置き換える） | はい | はい |

3. **割り当ての考え方**：解析を置き換える操作（`analyze_protocol` の `force_refresh`、`cache_protocol_analysis`、見出しの英訳の変更）は、前の解析を履歴（`analysis_history`）に残すので破壊的としない。読み取り専用としたツールのうち `search_studies` と `plan_study_search` は、利用者辞書があるときだけ未一致語の記録を書く。これは診断用の記録であり、利用者が保持するものを変えないので、読み取り専用のままとする。
4. **進捗通知**：クライアントが進捗を求めた呼び出し（`progressToken` 付き）に、次の時点で進捗を送る。求めていない呼び出しには送らない。
   - `compare_protocols`：一次判定の各研究のプロトコルを取得する前（`n 件中 k 件目`、研究 ID）。EMA への間隔（2 秒以上）のため、研究の数だけ時間がかかる。`check_protocols` で Study documents を確かめるときも同じ。
   - `analyze_protocol`（サーバー側抽出）：待機の間、終わったバッチの数が変わるたび（`total 中 done`）。
5. **対象外**：`research_protocol` の進捗は送らない（全文の一括回答は終わったバッチの数を持たない）。ツールの数と引数は変えない。進捗の受け口（`ctx`）は入力スキーマに現れない。CLI は進捗を表示しない。
