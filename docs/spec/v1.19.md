# v1.19 追加要件：結果への版の記録、同梱カタログの更新の仕方、アプリの新しい版の通知

2026-11-20。v1.18 に加える。
[コードとデータを別々に版管理する実装計画](../research/202610081527_code_data_versioning_plan.md)の段階 4 と 5。カタログが月ごとに自動で入れ替わるようになった（v1.18）ので、同じ質問の結果が後で変わったときに、何が変わったのかを追えるようにする。実測は[検証記録](../validation.md) の 2026-11-20 の節。

1. **結果に、それを作った版を記録する**：記録するのは、アプリの版（`app_version`）、カタログのスナップショットの日付（`catalogue_snapshot`。日付付きのエクスポートが無い DB では `null`）、PDF の parser の版（`parser_version`）、抽出スキーマの版（`schema_version`）。
   - 解析：`source` に `app_version`、`catalogue_snapshot`、`parser_version` を加える（`schema_version` は以前からある）。保存済みの解析を返すときは、保存したときの値のままとする（作った版の記録であり、今の版ではない）。
   - 質問別回答：`versions` を加える。
   - 比較：`versions` を加える（`comparison.json` と各研究の JSON の上位、ツールの応答）。比較表の Markdown の末尾に `作成時の版: ema-rwe-mcp X; カタログ YYYYMMDD; parser P` の 1 行を加える。後から `get_protocol_comparison` で集め直しても、作成時の値のままとする。
   - fingerprint は変えない（PDF、抽出の設定、parser は以前から含む。カタログの日付は、PDF の解析の同一性に関わらない）。記録の無い古い解析と比較は、そのまま読める。
2. **同梱カタログは、公開したスナップショットそのものにする**：月ごとの更新は、スナップショットの公開だけで行い、`data/ema.sqlite3` を月ごとにコミットしない。同梱 DB（オフラインでの最初の起動のため）は、アプリのリリースのときに、最新のスナップショットを検証して展開したファイルに置き換える（`scripts/build_catalogue_snapshot.py --verify <フォルダ> --unpack-to data/ema.sqlite3`。検証に通らなければ何も置き換えない）。同梱 DB と、利用者が取り込むスナップショットは、同じ内容になる。
3. **月ごとのスナップショットの元**：補完の結果（プロトコルから補った医薬品）は、前のスナップショットから引き継ぐ。保守者は、作業用の DB に最新のスナップショットを取り込み（`update-catalogue`）、新しいエクスポートを取り込み（`import-all`）、必要なら補完を実行し（`backfill-protocols`）、その DB を `--observations-from` に渡してスナップショットを作る。手順は `docs/release.md`。
4. **アプリの新しい版を知らせる**：カタログの確認（v1.18）で取得するリリースの一覧から、公開済みの `vX.Y.Z` の最大を記録する（`update.latest_app_version`）。動いている版より新しければ、`catalogue_status` に `app_update_available`（`current`、`latest`、利用者への伝え方 `instruction`）を加える。新しくなければ、この項目は無い。`catalogue_status` は `app_version` を常に返す。
5. **アプリは自動で置き換えない**：サーバーは、自分自身を更新しない。利用者が、MCP クライアントの設定の固定タグを書き換えて再起動する（固定していない `uvx` は、`uvx --refresh` で 1 回起動する）。呼出元は、`app_update_available` があれば、その `instruction` に沿って利用者に 1 回伝える。
6. **追加の通信は無い**：版の確認は、カタログの確認と同じ 1 回の要求（リリースの一覧）で行う。`EMA_CATALOGUE_UPDATE=off` のときは、アプリの新しい版も知らせない。手で取得したスナップショット（`--file`）の取り込みでは、一覧を取得しないので、前回の記録を保つ。
