# v1.32 追加要件：コード表の網羅と、本文の無い PDF

2026-11-22。v1.31 に加える。
claims の全件の抽出（`docs/validation.md` の 2026-11-22）で、付録のコード表がバッチに入っていても事実にならない研究が多く見つかった。また、文字のあるページが 1 枚だけのスキャンの PDF で、中身の無い解析が保存された。ここには、変わった挙動だけを書く。

1. **コード表のページ**：異なるコード（ATC、ICD-10、ドット付きの ICD-9）が 8 個以上並ぶページを、コード表のページとする。判定は正規表現による目安で、参考文献や数値の表を拾うことがある。
2. **最初のバッチの `code_pages`**：呼出元の抽出で最初のバッチ（offset 0）は、PDF 全体のコード表のページの一覧 `code_pages` を返す。指示文は、コード表を条件ごとに 1 件の `disease_definitions`（全コードと体系を値に書く）にし、バッチの外のページは `read_protocol_text` で読むよう求める。
3. **未引用のコード表の注記**：解析を保存するとき（呼出元の `coverage_complete`、サーバー側の抽出のどちらも）、どの事実の引用も指していないコード表のページを `missing_information` に「Pages listing codes that no fact cites」として書く。保存は断らない（断るかどうかは、全件の注記の件数を見てから決める）。
4. **読む付録**：しおりのある PDF で、本文から参照されず、題もコード表らしくない付録でも、コード表のページなら読む順に入れる。parser の版（`structural-v24`）は上げない。上げると全研究の保存済みの解析が古い扱いになり、影響の無い研究まで抽出し直すことになるためである。影響のある研究は、対象を絞って抽出し直す。
5. **本文の無い PDF**：3 ページ以上ある PDF で、50 文字以上のページが 2 枚未満なら、文字の層が無いもの（`PDF_OCR_REQUIRED`）とする。承認記録の 1 ページだけが文字を持つスキャンや、本文が 1 語の黒塗りの PDF が当たる。`text_layer` は `none` になる。
6. **変えないもの**：ツールの引数、解析のスキーマ、保存と無効化の規則、逐語照合。
