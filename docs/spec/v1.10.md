# v1.10 追加要件：探索の読み方の固定、省いた所属薬の全件、種別ごとの取り込みの記録

2026-10-09。v1.9 に加える。
根拠は外部の再々々レビュー（9d69c3d）の 3 つの指摘と、実装方針へのレビュワーのコメント（[検証記録](../validation.md) の 2026-10-09 の節）。

1. **探索は一つの読み方で行う**（v1.8 を補う）：`research_protocol` は開始時の英訳で、全文の一括回答、呼出元に渡す最初の検索、内部 LLM の探索ループの `search`、`outline`、`read`、回答の引用の検証、キャッシュの鍵のすべてを行う。鍵の `reading` は、検証に使った英訳そのものから作る。途中で英訳が変わっても、別の読み方で読んだ結果が開始時の鍵で保存されることはない。
2. **探索ツールの応答は読み方を名乗る**：`get_protocol_outline`、`search_protocol_text`、`read_protocol_text` の `source.reading` に、その応答を作った読み方を入れる（入力の形は変えない）。呼出元は、`research_protocol` が返した `reading` と違う値を見たら、探索をやり直す。各ツールに期待する読み方を渡して拒否させることはしていない。呼出元が探索中の A→B→A を見落とせば、保存時の照合はすり抜ける（既知の制限）。
3. **省いた所属薬は全件返す**（v1.9 の 3 を改める）：`omitted_members` は件数で切らず、`omitted_members_total` はその件数と一致する。呼出元がクラスに属するかを判断するので、一部だけでは補完が終わらない。2026-10 の辞書とカタログでは最大 54 件（VACCINES、約 13 KB）。今後増えても、黙って打ち切る方式には戻さない。
4. **取り込みの記録は内容と種別ごと**：種別は互いに排他的でないので、ある種別のエクスポートが別の種別や全研究のエクスポートとバイト単位で同じことは正当にありうる。`imports` の鍵（列名は `checksum` のまま）は、種別のエクスポートでは `<SHA-256>:<種別>`、全研究のエクスポートでは `<SHA-256>` とする。同じ内容で種別が違うエクスポートはそれぞれ記録が残り、`catalogue_status` とスナップショットの manifest の件数が正しい。同じ種別の同じ内容を取り込み直すと、その記録だけが新しいファイル名と日時になる。原本（`raw/<SHA-256>.csv`）は内容だけで重複を除く。DB スキーマの版は 6 のままで、公開済みのスナップショットも読める。同梱 DB と既存の利用者 DB の旧形式の鍵（種別のエクスポートでもハッシュだけ）は残り、新しい鍵と並んでも、各種別の最新の記録を読むので害はない（`snapshot_count` が 1 増えるだけ）。`catalogue_status` の `latest_import.checksum` は、種別のエクスポートでは `<SHA-256>:<種別>` を示す。
