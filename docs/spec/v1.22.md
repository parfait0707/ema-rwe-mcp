# v1.22 追加要件：節のラベルの空白、空の最終統合の呼び出し

2026-11-20。v1.21 に加える。
正解データ（v1.20、v1.21）で、変更後の版の呼出元抽出を採点したときに、読み手の側で繰り返し起きた 2 つのつまずきを直す。実測は[検証記録](../validation.md) の 2026-11-20 の節。

1. **節のラベルは、空白を詰めて比べる**：根拠の `section` と、サーバーの節の見出しは、連続する空白を 1 つにしてから比べる。PDF の見出しは、番号と題の間に複数の空白を持つことがあり（`3.2.5.2   Real-world outcomes`）、読み手が空白 1 つで書き写すと、`EVIDENCE_INVALID`（Section does not match）で拒否されていた。別の節のラベルは、これまでどおり拒否する。`section` を null にする指示は変えない。
2. **空の最終統合の呼び出しで、保存済みの解析を置き換えない**：`cache_protocol_analysis` の `coverage_complete=true` の呼び出しで、キャッシュされたバッチが無く、渡された解析も空で、その研究に中身のある保存済みの解析があるときは、`INCOMPLETE_EXTRACTION` で断り、保存済みの解析を残す。統合はバッチを消すので、統合の後にもう一度同じ呼び出しをすると、空の解析が保存済みの解析を置き換えていた。やり直すには、`analyze_protocol` を `force_refresh=true` で呼び、全バッチをキャッシュし直す。解析の全体を 1 回の最終呼び出しで渡す使い方と、保存済みの解析が無いとき（または空のとき）の空の呼び出しは、これまでどおり受け付ける。
