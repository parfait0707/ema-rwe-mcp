# v1.1 追加要件：プロトコルの有無と読めるかによる順位付け、名前を主キーにした医薬品の照合

2026-10-02。医薬品入力の検索テスト（102ケース、PDF 79件）と、その再テストの結果に基づく。根拠は `docs/validation.md`（2026-10-02）を参照。v1.0 に加える。

1. **プロトコルの所在（`protocol_listed`）**：Studies export の `Protocol file(s)`・`Protocol file(s) - URI`・`Protocol URL` のいずれかに値があれば `true`、すべて空なら `false`、列が無ければ未設定とする。研究ページを読み直しても保持する。順位付けにだけ使い、最新版の選択には使わない。
2. **PDF のテキスト層（`protocol_text_layer`）**：`get_protocol` は PDF を取得するたびにテキスト層を判定し（`full`／`partial`／`none`）、応答の `protocol.text_layer` に返し、研究に記録する。`none` は全ページに実質的な文字が無い（画像だけで OCR が要る）ことを表す。
3. **順位付け**：`compare_protocols` の候補は削らず、次の順に並べる。
   1. プロトコルが公開されていないと確認された研究、または `protocol_text_layer=none` の研究を最後にする
   2. 固有語で一致したブロック数
   3. 役割の列で一致したブロック数
   4. `protocol_listed=false` を後ろにする
   5. 研究タイプの適合
   6. RRF で統合した BM25 の順位
   比較群として入力の薬を定義する研究は下げない（コホート・曝露の定義の参考になるため）。
4. **名前を主キーにした医薬品の照合**
   - EMA 医薬品辞書の照合は名前（製品名・成分の組み合わせ）だけで行い、ATC コードから辞書の製品を引かない。
   - EMA 辞書の記録が持つ ATC コードは、カタログの検索語にも `plan_study_search` の `code_searches` にもしない。プロトコル PDF の本文検索（`search_protocol_text`）のヒントとしてだけ残す。
   - カタログの検索語になる ATC コードは、カタログ自身が記録するもの（`medicines.py` のクラスのカテゴリー語）に限る。EMA 辞書のコードは、カタログ上のそのコードの名称と成分が食い違う場合は使わない。
5. **語全体での照合**：`compare_protocols` の各検索語と、応答の `query_expansions` は、検索語を1つの医薬品名として語全体で照合する。長い語の一部（glucagon-like の glucagon）には一致させない。末尾の塩・エステルの語（citrate、maleate、hydrochloride など）は除いて照合する。これは検索の手がかりで、塩と遊離体を同じ製剤とはみなさない。
6. **0件の医薬品の類縁概念**：単一ブロックで0件のとき、検索語に第5レベルの ATC コードがあれば、同じ第4レベルのクラスの名称（`broader`）と、カタログが記録する所属薬（`sibling`）を類縁概念として示す。名称の無いクラス、`combinations` などの一般的な名称は出さない。類縁概念が無いときの指示は、医薬品なら第5レベルの ATC を渡すか、同じ薬効群の薬を提案するよう求める。
7. **呼出元への指示**：医薬品は INN、EU・米国の製品名、略語、語形とハイフン表記の変種を渡し、DB に無い薬は第5レベルの ATC も渡すよう指示する。製品を依頼された場合は、成分だけで一致した候補（同じ成分の別製品）をユーザーに示すよう求める。
