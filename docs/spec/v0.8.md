# v0.8 追加要件：一次検索を全列・階層つきにし、候補を順位付けする

2026-09-28、ユーザーの仮説を正解集合（`tests/fixtures/gold/`、暫定ラベル）で検証した結果に基づく。仮説は次のとおり。

- 研究のタイトルとメタデータで可能性がある研究を広く拾い、ユーザーの求める情報を含みそうな研究を上位に並べ、その上位から PDF を読むのがよい。
- メタデータには、固有の病名・薬剤名ではなく、カテゴリー（上位概念、包括的なアウトカム名、薬効群）しか書かれていないことがある。
- 評価の詳細は `docs/validation.md`（2026-09-28）を参照。

1. **概念ブロック**：`compare_protocols` に `blocks: [{role, queries, category_terms}]` を追加する。ブロック内は OR、ブロック間は AND で検索する。従来の `queries`・`role`・`category_terms` は 1 ブロックとして扱う。
   - ブロックを使う場合、`queries`・`role`・`synonyms`・`codes`・`category_terms`・`match_scope=analogous` は併用できない。従来形式の検索語は 20 件まで、ブロックでは合計 40 件までとし、空白の語は受け付けない（空の検索語はカタログ全件に一致するため）。語はすべてブロックに書く。`synonyms` と `codes` は全クエリに適用されるため、ブロックをまたいで混ざってしまうからである。
2. **全列で拾う**：一次検索は全列で行い、役割（outcome／condition／exposure）は絞り込みでなく順位付けに使う。Outcomes 欄が空の研究（全体の 19%）を拾うためである。
   - `search_studies` は従来どおり、役割で列を絞る精密な検索として残す。
3. **カテゴリー語**：`category_terms`（ICD-10 のブロック・章名、MACE／AESI などの包括名、ATC の群名）を、固有語と同じく全列で検索する。
   - 呼出元の同義語とコードは適用しない。
   - 一致した語の出所は `category` とする。
4. **順位付け**：候補は切り詰めずに、次の順で並べる。候補ごとに `rank_features` を返す。
   1. プロトコルがないと確認された研究を最後にする
   2. 固有語で一致したブロック数が多いもの
   3. 役割の列で一致したブロック数が多いもの
   4. 研究タイプの適合（カタログのデータソース種別あり ＋1、調査・横断研究 −1）
   5. RRF（k=20）で統合した BM25 の順位
5. **プロトコルの有無の確認**：`check_protocols=N`（0〜20、既定 0）を指定すると、候補が一覧表示される場合に限り、上位 N 件の Study documents ページを確認して `protocol_available` を付ける。PDF は取得しない。`network_requests` には、実際に行った HTTP 要求の数（robots.txt・研究ページ・タブを含み、キャッシュの再利用は含まない）を入れ、確認した研究数は `protocols_checked` に入れる。介入研究に変わっていた研究（対象外）は `out_of_scope=true` とし、プロトコルがない研究と同様に最後に回す。類縁スコープでは確認しない。ユーザーが許容した範囲の通信である。
6. **複数ブロックで 0 件の場合**：`analogous_fallback.status=not_available_for_blocks` を返し、ブロックごとの検索か、カテゴリー語の追加を促す。類縁概念は、1 ブロックずつ扱う。
7. **呼出元への指示**：`client_expansion` の指示に、ブロックの分け方とカテゴリー語の選び方を加える。カテゴリー語は概念に固有のものにし、"adverse drug reactions" のような汎用語は使わない。カタログにはコードがほとんど現れない（コードのみの相対再現率 0.010）ことも明記する。

実測（同梱カタログ、正解集合 20 問、暫定ラベル）：製品の `compare_protocols` で、相対再現率 0.965（従来の役割別の列 0.858）、nDCG@5 0.920（RRF のみ 0.883）、上位 5 件の該当数 4.10（同 3.60）、平均候補数 144（同 65）。
