# v1.5 追加要件：プロトコルの構造推定の汎用化

2026-10-05。v1.4 に加える。
根拠は [修正案](../research/202610051802_structural_heuristics_generalization.md) と [レビュー](../research/20261005_structural_heuristics_review.md)。

1. **役割の三つの判断を分ける**：節の役割（`role`）は、読む対象、引用の受理、抽出の指示の三つに別々に使う。
   読む対象から外すのは contents、background、administrative、references、checklist で、unknown は本文に方法の手がかりがあるときだけ読む。
   conduct（倫理、有害事象の報告、結果の公表）と amendments（改訂）は読む。
   方法の事実の引用を `EVIDENCE_WRONG_SECTION` で拒否するのは、引用が references、contents、background、checklist にしか無いときに限る。
   各節に役割の根拠 `role_basis`（heading、bookmark、parent、page_type、none）を付ける。
2. **様式の章名の役割**：EMA の PASS プロトコル様式（EMA/623947/2012）の章名に役割を付ける。研究の目的は objectives、改訂は amendments、倫理と有害事象の報告と結果の公表は conduct、目次と表・図の一覧は contents とする。
3. **見出しの検出**：算用数字とローマ数字の節番号を共通の解析器で読む。
   1段の番号の行は、大文字の題名か、様式の章名と題名全体が一致するときに見出しとする。
   ローマ数字1段は、様式の章名か2語以上の大文字の題名に限る。
   先頭が 0 の数値は節番号とみなさない。
4. **構造の補完**：しおりが無いときは、目次の項目と本文の見出しの行との印字ページのずれが3項目以上かつ全体の2/5以上で一致した場合に限り、目次を構造として使う（`outline_source=toc`）。
   しおりも目次も無いときは、直前の章番号の次の番号で本文より大きいか太字の行を章見出しとする。
   しおりや目次の題名の行は節の始まりとし、その行より上の本文は前の章に属させる。
   表・図・目次の一覧のしおりは構造に使わない。
   章番号が親章と食い違う節は親の役割を継承しない。
   付録の参照による読む対象の絞り込みは、PDF 自身のしおりがあるときだけ行う。
5. **チェックリストの範囲**：チェックリストを名乗る見出しか ENCePP の題名の行のあと2ページ以内に、質問（`?` が5個以上）と回答欄（Yes/No/N/A）があるときだけ質問票とする。
   範囲はその行から次の付録、しおりや目次の項目、最上位の章見出しまでとし、同じページの前後の本文はそれぞれの節に残す。
   質問票の続かない行には `structure_warnings` を付けて本文として残す。
6. **抽出の指示**：amendments の節は旧条件と現行条件を分け、旧条件を現行条件として報告しない。conduct の節は研究固有の条件や定義を述べる箇所だけを扱う。
7. **キャッシュ**：parser の版（`structural-v13`）と探索の版（`source-role-exploration-v8`）を上げ、既存の解析と質問別回答は再抽出の対象にする。
8. **計測**：`scripts/structure_eval.py` で、PDF の SHA-256、parser 版、各指標の分母を記録して構造推定の精度を測る。開発側と評価側はテンプレートの系列で分け（`tests/fixtures/structure/split.json`）、評価側のラベル（`tests/fixtures/structure/labels.json`）は実装と独立に作る。
