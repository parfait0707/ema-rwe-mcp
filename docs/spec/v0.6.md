# v0.6 追加要件：クライアント翻訳を既定にし、疾患辞書は利用者の任意にする

2026-09-27 のユーザー判断で、v0.5 までの「同梱の日本語疾患辞書（`data/terminology.json`）を既定で読み込む」方針を改める。理由は次の 3 点である。

- 21 概念の類縁分類に出典がなかった。
- WHO ICD-10 の分類名称を公開配布することのライセンスが未確認だった。
- 辞書の保守をリポジトリで抱えない。

用語体系の比較は [research/202609270400_terminology_sources.md](../research/202609270400_terminology_sources.md) を参照。

1. **疾患辞書を同梱しない**。
   - 既定では概念辞書を読み込まない。
   - 読み込むのは、`EMA_TERMINOLOGY_PATH`（ファイル、または `*.json` を含むフォルダ）か、データフォルダ内の `dictionaries/*.json`（Git 追跡外）があるときだけとする。
   - 複数ファイルは統合し、内容のハッシュを `terminology_revision` に含める。
   - wheel には同梱しない（`SEEDED_FILES` と `force-include` から外す）。
   - 読み込み中の辞書名は、`catalogue_status.dictionaries` と `plan_study_search.dictionaries` で返す。
2. **記入例**。旧 `data/terminology.json` を `data/terminology.example.json` へ移し、WHO ICD-10 の分類名称（`code_candidates[].label`、54 件）を削除した。コードと出典 URL は残す。既定では読み込まない。`scripts/mine_terminology.py` はこの記入例を対象にする。
3. **クライアント翻訳**。
   - 日本語の質問で、利用者辞書の概念に一致しないものは、研究デザイン語が訳せても `status=needs_client_translation` とする。
   - `plan_study_search` は `client_expansion: {required, instruction}` を返す。指示には **ICD-10（WHO 2019）を手がかりに類義語を探索する**指針を含める。
     - 該当する 3 桁分類・4 桁細分類の名称と包含用語を類義語にする。
     - Excludes の語は類義語にしない。
     - 同じブロックの別分類は `sibling`、ブロック・章は `broader`、合併症・関連病態は `associated` の類縁概念とする。
     - 各国修正版（ICD-10-CM、-GM、日本の対応版）との差に注意する。
   - 同じ指針を、`use_llm=true` の計画プロンプト、`analogous_fallback` の `no_analogous_terms` 指示、MCP の `instructions` に入れる。
   - `method` は `client_expansion`、または利用者辞書に一致したときは `user_dictionary` とする。
4. **一致語の出所**。結果行に `matched_term_sources`（語 → `query`／`caller`／`vocabulary`／`dictionary:<ファイル名>`／`ema_medicines`／`llm`）を追加する。`query` は検索クエリ文字列そのもので、クライアントが渡した英語名を含む。ただしクエリ文字列が展開語と同じ場合は、その展開語の出所を返す（例：`cohort` は `vocabulary`）。利用者辞書のコード候補も `dictionary:<ファイル名>` とする。
5. **広義の臨床語グループを削除**。`vocabulary.GROUPS` から diabetes／bleeding／cancer を削除した。辞書がないと v0.5 の抑止（辞書概念の入力語の内側では発火させない）が効かず、「1型糖尿病」が糖尿病全般を拾う問題が戻るため。研究デザイン・手法・集団の語は残す。
6. **未一致語ログ**。概念辞書を設定しているときだけ記録する。辞書がなければ、日本語の質問はすべて設計上「未一致」になるため。
7. **辞書フォルダの扱い**。ドットで始まるファイルは読まない。不正な辞書は該当ファイル名付きのエラーにする。空の辞書ファイルも「設定済み」として扱う。`EMA_TERMINOLOGY_PATH` が存在しない場合も、`catalogue_status` は例外を投げず `dictionaries.error` で報告する。`use_llm=true` で計画した場合は `client_expansion.required=false` とする。
8. **EMA 医薬品辞書**（`data/ema-medicines.json`）は既定のまま残す。

見送り（ユーザー判断）：WHO ICD-API の照会機能。ICD-10 は ID 指定での取得と親子関係の取得だけで、語句からの検索がなく、日本語にも対応しないため。

互換性：
- 辞書由来の展開（49 概念の英語名・関連語・コード候補）は既定から外れる。以前と同じ挙動が必要な利用者は、記入例を `data/dictionaries/` にコピーする。
- 記入例には ICD-10 の名称がないため、`code_candidates[].label` は空になる。
