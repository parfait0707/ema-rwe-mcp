# v1.11 追加要件：途中バッチの保存、読み残しの検出、抽出と質問回答の一括化

2026-11-19。v1.10 に加える。
根拠は、呼出元抽出の所要時間と途中経過の保存についての検討と、4 件の実プロトコルでの比較（[検証記録](../validation.md) の 2026-11-19 の節）。

1. **途中バッチは DB に保存する**：`cache_protocol_analysis(batch_offset=...)` のバッチは、利用者側の表 `extraction_batches`（研究、fingerprint、読み方、種別、offset が鍵）に保存する。サーバーの再起動、別プロセス（CLI は呼び出しごとに別プロセス）、文脈の圧縮のどれでも失わない。カタログの表ではなく、スキーマの版にも含めない（`protocol_answers` と同じ扱い）ので、カタログの差し替えで消えず、公開済みのスナップショットも読める。
2. **保存したバッチは、同じ PDF・抽出設定・読み方のものだけを結合する**：別の fingerprint か読み方のバッチを保存した時点で、その研究の古いバッチを消す。解析を保存したとき、見出しの英訳が変わったときも、その研究のバッチを消す。
3. **読んでいないバッチがあれば結合しない**：`analyze_protocol` は、返したバッチの offset と `next_offset` を記録する。`coverage_complete=true` の呼び出しは、offset 0 から `next_offset` をたどり、保存していないバッチがあれば `INCOMPLETE_EXTRACTION` を返して、読むべき offset を示す。解析は保存しない（保存済みのバッチは残る）。offset を付けずに最後のバッチを渡す従来の呼び方は、文書の末尾まで届く 1 バッチの代わりとしてだけ認める。バッチを 1 つも保存せずに全体を 1 回で渡す呼び方は、従来どおり受け付ける（サーバーは網羅を確かめられない）。
4. **配信していない offset のバッチは受け付けない**：`batch_offset` は、その PDF・抽出設定・読み方で `analyze_protocol` が返した offset に限る。それ以外は `INVALID_INPUT`。
5. **抽出と質問回答を 1 回で行える**：`analyze_protocol(question=...)` は、抽出の指示に質問と回答のスキーマ（`answer_schema`）を加える。呼出元は、各バッチの `cache_protocol_analysis` に `question` と、そのバッチが質問について述べる内容（`answer`、無ければ `answers=[]`）を渡す。回答の引用は解析と同じ規則で検証する。`coverage_complete=true` の呼び出し（`question` を渡す）は、バッチの回答を offset の順に結合し、`research_protocol` と同じ鍵（PDF、質問、読み方）で保存して、`answer_saved` を返す。回答が空なら保存せず `answer_saved=false` を返し、呼出元は `research_protocol` で探索する。30 件を超える回答と 120 件を超える種別判定は切り、その件数を `missing_information` に残す。
6. **質問は抽出を狭めない**：質問を渡しても、解析はスキーマの全項目を埋める。指示にそう書く。
7. **比較の `pending_tools` は研究ごとに 1 つ**：解析も回答も無い研究には、`analyze_protocol` を質問付きで 1 つだけ出す。内部 LLM を設定した構成では、抽出はサーバー側で行われるので、従来どおり `analyze_protocol` と `research_protocol` の 2 つを出す。解析だけがある研究には `research_protocol` を出す。
8. **採用しなかった方式**：引用を行番号で指定する方式（節の本文に行番号を付け、呼出元は `<section_id>:<行の範囲>` を返し、サーバーが逐語引用に展開する）は、同じ比較で所要時間が縮まらず、検証エラーが増えたので採用しない。引用は従来どおり逐語で受け取る。
