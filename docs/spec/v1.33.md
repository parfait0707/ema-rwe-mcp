# v1.33 追加要件：コード表の位置の行と章の地図

2026-11-23。v1.32 に加える。
コード表を事前に書き写すと、研究ごとに多くのトークンがかかる。コード表は位置だけを持ち、問われたときにそのページだけを読む。設計と根拠は `docs/research/202611231900_code_table_locations_plan.md`。ここには、変わった挙動だけを書く。

1. **位置の行（`code_table`）**：手元の PDF の解析（節、しおり、節の役割）だけで、LLM を使わずに作る。次の節を、同じ見出しの下で続くページごとに 1 行にまとめる。ページ数に上限は置かない。
   - コードを含む節が続き、合わせて異なるコードが 8 個以上並ぶ（v1.32 のコード表の判定）。本文の章にある表も入る。
   - 見出しの最も深い題がコードの表を名乗り（`codes`、`code list`、体系の名）、コードを 1 つ以上含む。
   - 付録で、最も深い題が用語の一覧を名乗る（`MedDRA`、`preferred terms`、`terms`、`code list`、`SMQ`）。数字のコードが 3 個未満なら `kind` は `terms`、それ以外は `codes`。
   - 表の題の行がしおりの 1 ページ前に印字されている（題の行だけの 1 節が、しおりの祖先の下にあり、すぐ後にそのしおりの表が続く）ときは、そのページから行を始める。
   - 参考文献、目次、チェックリストの節は入れない。文中に 1 つ 2 つ書かれたコード（除外基準の N18.5 など）は行にしない。これは事実の行で扱う。
2. **行の形**：`value` は見出し（しおりの階層 `chapter_path`、しおりが名乗らない本文の見出しは後ろに足す）、`page` と `end_page`、最初の節の `section_id`、`kind`、`systems`、`systems_inferred`、`evidence`（最初のページの、見出しを名乗る行 1 行の逐語引用。無ければそのページの 8 文字以上の最初の行）、`status`（`verified_local`）、`extractor`（`structure`）、`parser_version`、`app_version`。
3. **コード体系の目印**：体系ごとの表（見出しの語とコードの形）で判定する。ICD-10、ICD-9、ICD-11、ATC、MedDRA、CPT/HCPCS、NDC、OPCS-4、Read、SNOMED CT。見出しか本文で名乗られた体系と、形が固有の体系（ATC の 7 桁、NDC）を `systems` に入れる。どれも無いときだけ、他と紛れる形（文字＋2 桁は ICD-10 と OPCS-4、3 桁＋小数は ICD-9 と他の数）からの推定を `systems_inferred` に入れる。形の無い体系（ICD-11、OPCS-4、Read、SNOMED CT）は名乗られたときだけ付く。目印であり、呼出元はページを読んでから体系を確かめる。
4. **章の地図（`section_map`）**：同じ見出しの下で続く節を 1 行にまとめ、役割が `population`、`definitions`、`methods`、`data_sources`、`analysis`、`objectives`、`appendix`、`amendments`、`conduct`、`abstract` のものを入れる。行には `role` が付く（`kind` と体系は無い）。役割は見出しの語から判定するので外れることがある。
5. **作る時と置き場所**：最新のプロトコルを保存したとき（`get_protocol`、`prefetch-protocols`）に作り、研究の `protocol_observations` に `locations`（`protocol_id`、見出しの翻訳の `reading`、規則の版 `version`、`parser_version`、`app_version`、`code_tables`、`section_map`）として保存する。v1.33 より前に保存した PDF は、`find_facts` が `study_ids` で名指しされた研究を初めて読むときに作って保存する。同じ `protocol_id`・`reading`・`version` の保存済みのものは作り直さない。PDF が手元に無いか読めなければ作らない。`locations` は他のデータベースへ渡す観測（`SHAREABLE_OBSERVATIONS`）に入れない。配る事実（`prebuilt_facts`）にも入れない。
6. **`find_facts` と CLI `facts`**：`item_kinds` に `code_table` と `section_map` を足す。位置の行は `item_kinds` で求められたときだけ返す（省略時は今までどおり事実の行だけ）。研究の解析のプロトコル、解析が無ければ観測の最新のプロトコルの行を返す。`study_ids` を渡さない呼び出し（`source_types`、全件）では保存済みのものだけを使い、作らない（数百の PDF を 1 回の呼び出しで解析しないため）。位置の行を求めた応答には `no_locations`（位置の行が無い研究）が付く。`text` は値と引用に当たる。
7. **抽出の指示**：呼出元の抽出の最初のバッチは、`code_pages` の代わりに `code_tables`（`value`、`kind`、`page`、`end_page`、`systems`、`systems_inferred`）を返す。指示文は「位置の行になるコード表は書き写さない。`disease_definitions` には条件と定義の論理を書き、引用は表の見出しか定義の文にする。選択・除外基準や本文の定義の文中のコードは値に書く」に変わる。サーバー側の抽出の指示（`EXTRACTION_PROMPT`）は変えない。解析の指紋に含まれ、変えると保存済みの解析がすべて古い扱いになるためである。
8. **未引用のコード表の注記**：v1.32 の 3 の注記は、位置の行が覆うページを数えない。注記の文は「Pages listing codes that no fact cites and no code table row covers」になる。
9. **変えないもの**：parser の版（`structural-v24`）、解析のスキーマ、保存済みの事実（抽出し直さない）、逐語照合、配る事実。
