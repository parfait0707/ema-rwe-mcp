# v0.3 追加要件

ユーザーの2026-09-14の追加要望により、v0.2の次の部分を更新する。背景は、Studies exportだけではData source typeを判定できず、MCP経由の検索で一次判定上限（既定5件）まで絞り込めなかったこと。

1. EMA検索画面でData source typeをclaims／EHR／registryに限定したStudies exportを、種別ごとに`data/imports/source_type/<日付>_<claims|ehr|registry>_export-data.csv`へ保存し、ファイル名に埋め込んだ種別を各研究のカタログタグにする。exportの列構成は全件exportと同一で、種別列は存在しない。ファイル名の種別トークンは1つだけ許す。
2. 全件export（`data/imports/studies/`）を先に、種別exportを後に取り込む。種別exportは既存研究の`data_source_types`に種別を累積し、由来（ファイル名・SHA256）と確認日時を記録する。その後に全件exportを再取込してもタグは保持する。CLIの`ema-rwe import-all`が両フォルダの全CSVをこの順で取り込む。
3. `filters.data_source_types`の意味を「PDF判定後のonly指定」から**カタログ段階の絞り込み**に変更する。値はclaims／ehr／registry／othersの4種で、othersは3種別のexportいずれにも含まれない研究。`source_preference`（PDF由来の優先／限定）とは独立し、併用できる。旧`drug_dispensing_prescription`の絞り込み値は廃止し、該当研究はothersとして扱う。
4. 候補数が一次判定上限を超えたら、`facets`の件数を示しながらデータソース種別（claims／ehr／registry／others）と実施国の**両方**をユーザーに尋ね、回答を`filters`へ渡して同じ検索語集合で再実行する。研究デザインや臨床条件はさらなる絞り込みに使う。任意のN件を黙って選ばない。
5. カタログDB`data/ema.sqlite3`をGit管理し、cloneした直後から検索と絞り込みを使えるようにする。チェックアウト内では`EMA_DB_PATH`未設定時の既定パスとし、wheel導入時だけOSのユーザーデータディレクトリへ退避する。`data/imports/{studies,source_type}/`は空フォルダ（`.gitkeep`）だけを追跡し、CSV本体・原本アーカイブ・PDFは追跡しない。
6. `catalogue_status`は`source_type_import_directory`と取込済み種別（`source_type_imports`）を返す。`import_catalogue_csv`は`studies/`と`source_type/`直下のファイル名だけを受け付け、`source_type/`のファイル名から種別を解決できない場合はエラーにする。

MCPは17 toolのまま。取込結果（2026-09-13 export）はNon-interventional 3,312件、claims 819件、ehr 914件、registry 536件、タグなし1,513件。詳細は[用途別分類](../source-types.md)、[比較](../comparisons.md)、[検証記録](../validation.md)を参照。
