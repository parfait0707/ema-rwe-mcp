# v1.6 追加要件：英語以外のプロトコルの見出しの翻訳

2026-10-06。v1.5 に加える。

1. **見出しの翻訳で役割を判定する**：節の役割は英語の語で見出しから判定するので、本文が英語でない文書（v1.5 の判定）では、見出しの英訳から役割を判定する。
   翻訳の対象は、節の見出しとしおりの題名（`heading_texts`）である。
   節の見出しとして返す文字列と引用の節名は、文書の原文のままとする。
   翻訳のある文書では、unknown の節を読む条件は英語の文書と同じにする（v1.5 の「英語でない文書では unknown の節も読む」は、翻訳の無い文書に限る）。
   役割の語が見出しの6割超を認識できない文書では、翻訳があっても unknown の節を読む。
2. **翻訳の取得**：`analyze_protocol` は、言語を判定していない PDF について、抽出の前に一度だけ言語を判定する。
   内部 LLM があれば、その LLM が見出しを英訳する（200 件ずつ）。
   内部 LLM が無ければ `status=needs_heading_translation` と見出しの一覧を返し、呼び出し側が英訳して新しいツール `cache_heading_translations(protocol_id, translations)` で保存する。
   翻訳できない呼び出し側は `translations={}` を渡し、その文書は翻訳の無い文書として読む。
   一覧に無い見出しの訳、改行を含む訳、300 字を超える訳は捨て、その件数を `ignored_entries` で返す。
   英語の文書への翻訳は `INVALID_INPUT` で拒否する。
3. **保存とキャッシュ**：判定の結果と翻訳は、保存した PDF の隣（`<protocol_id>.headings`）に parser の版とともに置く。parser の版が変わったら判定し直す。
   翻訳は抽出の fingerprint に入れない。比較表は翻訳より前に各研究の fingerprint を記録するので、入れると翻訳した研究がすべて `COMPARISON_SOURCE_CHANGED` になる。
   代わりに、翻訳を別の内容で保存し直したときは、その PDF の保存済みの解析と、途中まで保存したバッチを破棄する。
   既に解析を保存した文書は、`force_refresh` するまで保存した解析を返す（翻訳の無いときの解析は、読む節が翻訳ありの場合を含む）。
4. **探索の道具**：`get_protocol_outline`、`search_protocol_text`、`read_protocol_text`、`research_protocol` も、保存された翻訳で役割を判定する。質問別回答のキャッシュの鍵には翻訳を含めない。
