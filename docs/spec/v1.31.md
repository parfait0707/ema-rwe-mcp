# v1.31 追加要件：証拠ストア（claims から）

2026-11-21。v1.30 に加える。v0.6.0 で入る。
設計の正本は[再設計案](../research/202611202312_redesign_proposal.md)（所有者の決定は 16 節）。ここには、変わった挙動だけを書く。
目的は、問い合わせのたびに PDF を読まずに答えられる問いを増やし、その問いを 3 分以内に返すことである（論点 4 の (a)）。
最初の対象は、カタログの source type が claims の研究である。速度と正確性を確かめてから他の source type へ広げる。

1. **事実の行**：保存済みの解析（`analyses`）を、事実 1 件 = 1 行に展開して返す。行の項目は、研究 ID、PDF の ID と SHA-256、項目種別、値、物理ページ、節のラベル、逐語引用、状態、来歴（抽出器、parser、アプリの版）である。項目種別はスキーマ 0.3 の項目から決まる（`study_design`、`cohort.inclusion`、`cohort.exclusion`、`cohort.index_date`、`cohort.baseline_period`、`cohort.follow_up`、`cohort.time_window`、`population`、`exposure`、`comparator`、`outcome`、`data_source`、`disease_definition`、`statistical_analysis`、`key_note`）。`data_source` の行は `usage`（used、planned、candidate、unclear）を持ち、計画と実際の使用を混同しない。`missing_information` は `missing` の行として返す。行は解析から読むたびに導き、別の表に複製しない。解析が無効になれば、その行も消える。
2. **事実の検索**（MCP `find_facts`、CLI `facts`）：研究 ID、項目種別、source type、語（値と引用の部分一致、大文字小文字を区別しない。配布する事実は照合の時点で引用を持たないので値だけ）で絞り、事実の行を返す。研究 ID を渡したときは source type を使わない。source type はカタログの検索の絞り込みと同じ分類で判定する。研究ごとに、事実が手元の解析か配布物か、どちらにも無いかを返す。どちらにも無い研究は落とさず `no_facts` に並べる。ネットワークに出ない。
3. **配布する事実**（`prebuilt_facts` 表）：保守者が作る事実の行で、逐語引用の文字列を持たない（論点 2 の (a)）。持つのは、値、物理ページ、節のラベル、引用の位置（正規化したページ本文の中の開始と終了）、正規化した引用の SHA-256 と長さ、作成日時、来歴である。カタログの表として扱い、この表を持つスナップショットの取り込みでだけ置き換わる（持たないスナップショットでは手元の分が残る）。手元の解析がある研究では、手元の事実を優先する。
4. **引用の復元**：配布の事実は、同じ SHA-256 の PDF が手元にあるとき、位置から引用を切り出し、ハッシュが合えば `verified_local` として引用を付けて返す。合わなければ同じページの中を同じ長さでずらして探す。見つからない、または PDF が手元に無い事実は `verified_at_build` として引用なしで返し、`quote_note` で「引用は PDF 取得後に表示」と示す。1 つの事実の引用のうち 1 つでも合わなければ、その事実は `verified_at_build` のままとする。引用を持たない事実（`missing` の行、根拠の無い事実）は `no_quote` とする。`AGENTS.md` の逐語引用の要件は、`verified_local` の行で満たす。
5. **配布する事実の作成**（CLI `export-facts`）：保守者が、手元の解析と保存済み PDF から `prebuilt_facts` を作り、指定したデータベースへ書く。引用の位置が求まらない事実は書かない（`facts_without_position` に件数を報告する）。PDF が手元に無い研究は書かず `studies_without_pdf` に並べ、出力先にあるその研究の行は残す。
6. **プロトコルの事前取得**（CLI `prefetch-protocols --source-type claims|ehr|registry`、研究の間隔は既定 30 秒）：その source type で Study documents にプロトコルがある研究の最新プロトコルを、研究ごとに取得して保存する。取得済みの研究と、プロトコルが無いと分かった研究は飛ばすので、途中で止めても再開できる。HTTP 層の再試行を使い切った 429（`EMA_RATE_LIMITED`）が出たら、研究の間隔を 1 分に広げて（その実行の間は戻さない）同じ研究を取り直す。続けて 429 なら 15 分休んで再開する（論点 1）。15 分の休みを 3 回した後にまた 429 が出たら、実行を止めて `stopped` に記録する。それ以外の障害は記録して次の研究へ進む。検索の中では動かない。`AGENTS.md` の取得方針の例外に加える。
7. **手元の静的ページ**（CLI `facts-site`）：事実の行から、読み取り専用の HTML を 1 枚書く。外部の資源を読み込まず、公開はしない（論点 5 の (b)）。
8. **変えないもの**：既存のツールの引数と応答の形、解析の保存と無効化の規則、逐語照合の正規化、API キー不要の呼出元経路を既定とすること。判定モデル（論点 6）は v0.6.0 には入れない。
