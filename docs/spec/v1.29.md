# v1.29 追加要件：バッチを 1 つも保存していない最後の呼び出し

2026-11-20。v1.28 に加える。
呼出元の抽出で、複数のバッチに分かれるプロトコルのバッチを配信した後、どのバッチも保存せずに `cache_protocol_analysis(coverage_complete=true)` を呼ぶと、読み残しの検査が行われず、渡した解析（空でもよい）がそのまま `status=analyzed` で保存されていた。v1.11 の 3（読んでいないバッチがあれば統合しない）は、保存したバッチが 1 つ以上あるときにしか働いていなかった。v0.5.8 のリリース前の採点で見つかった。ここには、変わった挙動だけを書く。実測は[検証記録](../validation.md) の「バッチを 1 つも保存していない最後の呼び出し」の節。

1. **配信の記録があれば検査する**：最後の呼び出しの読み残しの検査を、保存したバッチがあるときに加えて、その研究に配信したバッチの記録があるときにも行う。最初の offset から順に、保存したバッチか、offset なしで渡す「プロトコルの終わりまで届く 1 つのバッチ」で覆われていなければ、`INCOMPLETE_EXTRACTION` で断り、読まれていない最初の offset を伝える。何も保存しない。
2. **変えないもの**：配信の記録も保存したバッチも無いとき（統合でバッチが消えた後に、解析の全体を 1 回の最後の呼び出しで渡して置き換えるとき）の扱い、v1.22 の空の最後の呼び出しの扱い、ツールの引数と応答の形。
