# v1.29 追加要件：バッチを 1 つも保存していない、空の最後の呼び出し

2026-11-20。v1.28 に加える。
呼出元の抽出で、複数のバッチに分かれるプロトコルのバッチを配信した後、どのバッチも保存せずに、空の解析で `cache_protocol_analysis(coverage_complete=true)` を呼ぶと、空の解析が `status=analyzed` で保存されていた。v1.11 の 3 は、バッチを 1 つも保存せずに解析の全体を 1 回で渡す呼び方を受け付ける（サーバーは網羅を確かめられない）。空の解析はその「全体」に当たらないが、区別していなかった。v0.5.8 のリリース前の採点で見つかった。ここには、変わった挙動だけを書く。実測は[検証記録](../validation.md) の「バッチを 1 つも保存していない最後の呼び出し」の節。

1. **空の最後の呼び出しは、配信の記録で検査する**：保存したバッチが無く、渡した解析が空（`missing_information` だけのものを含む。v1.22 と同じ判定）で、その研究に配信したバッチの記録があるとき、v1.11 の 3 の読み残しの検査を行う。最初の offset から順に、offset なしで渡す「プロトコルの終わりまで届く 1 つのバッチ」で覆われていなければ、`INCOMPLETE_EXTRACTION` で断り、読まれていない最初の offset を伝える。解析は保存しない。1 つのバッチで終わるプロトコルの空の最後の呼び出しは、これまでどおり受け付ける。
2. **変えないもの**：バッチを 1 つも保存せずに中身のある解析の全体を 1 回で渡す呼び方（v1.11 の 3、v1.22）は、配信の記録があっても、これまでどおり受け付ける。配信の記録も保存したバッチも無いとき（統合でバッチが消えた後）の扱い、v1.22 の空の最後の呼び出しの扱い（保存済みの解析を守る）、保存したバッチがあるときの検査、ツールの引数と応答の形。
