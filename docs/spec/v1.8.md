# v1.8 追加要件：見出しの読み方の整合性

2026-10-08。v1.7 に加える。
根拠は [再々レビュー](../research/202610082232_pr65_pr66_rereview_implementation_plan.md) の指摘 1 と、[評価と実装計画](../research/202610082250_rereview_response_plan.md)。

1. **読み方の記録は DB に置く**：PDF ごとの言語の判定と見出しの英訳（v1.6）は、利用者の DB の表 `protocol_readings` に置く。読み方 `reading` は、英訳をキー順に並べた JSON の SHA-256 で、英訳の無い文書（英語の文書と、英訳しなかった文書）は空文字とする。
   以前の版が PDF の隣に置いた `<protocol_id>.headings` は、DB に記録が無いときに一度だけ取り込む。DB の記録は上書きしない。
   カタログの差し替え（同梱 DB、スナップショット）はこの表に触れない。
2. **英訳の変更と解析の失効は一つのトランザクションで行う**：`cache_heading_translations` は、`BEGIN IMMEDIATE` の中で読み方を比べ、変わっていれば記録を書き換え、その PDF の保存済みの解析を失効させる（履歴は残す）。同じプロセスの途中のバッチとサーバー側の抽出も取り消す（v1.7 の 5）。
3. **解析は抽出したときの読み方のままのときだけ保存する**：解析の `source.reading` に、抽出に使った読み方を記録する。保存は `BEGIN IMMEDIATE` の中で DB の今の読み方と照合し、違えば `READING_CONTEXT_CHANGED` を返して保存しない。照合と保存の間に別のプロセスが割り込めないので、DB を共有する別のサーバープロセスが英訳を変えても、古い読み方の解析は保存されない。
   照合は読み方の内容で行う。英訳を A から B に変えて A に戻した後は、A のときに始めた抽出を保存できる（今の読み方と一致するため）。B のときに始めた抽出は保存できない。
4. **キャッシュも読み方を照合する**：保存済みの解析は、fingerprint と読み方の両方が今と一致するときだけキャッシュとして返す。読み方を記録していない解析（v1.7 以前）は、英訳の無い読み方（空文字）で抽出したものとみなす。英語の文書の既存の解析はそのまま使え、英訳のある文書の解析は抽出し直す。
5. **呼び出し側の抽出は読み方を返す**：`analyze_protocol` のバッチの `source.reading` を、`cache_protocol_analysis` の新しい引数 `reading` に渡す（CLI は `cache-analysis --reading`）。英語の文書では省略してよい。英語以外の文書で、渡された読み方が今と違う（省略を含む）ときは、途中のバッチも含めて受け付けない。途中のバッチは `(研究, fingerprint, 読み方)` ごとに持つ。
6. **サーバー側の抽出**：タスクは開始時の英訳で PDF を読み、その読み方で保存する。タスクは `(研究, fingerprint, 読み方)` ごとに持ち、読み方が変われば古いタスクを取り消して新しく始める。
7. **比較表も読み方を照合する**：`get_protocol_comparison` は、保存済みの解析の読み方が今と違えば、その解析を使わず `analyze_protocol` を未処理のツールに挙げる。
8. **質問別回答は読み方ごとに保存する**：英訳がある PDF では、回答のキャッシュの鍵に読み方を含める。`research_protocol` は質問ごとに一度だけ英訳を読み、その読み方で探索して保存する。`needs_client_exploration` は `reading` を返し、呼び出し側は `cache_protocol_answer` の新しい引数 `reading` に渡す（CLI は `cache-answer --reading`。英語以外の文書では必須）。古い読み方の回答は古い鍵で保存されるので、今の英訳の下では返らない。
9. **言語の判定は保存済みの英訳を上書きしない**：内部 LLM による最初の英訳は、その間に（別のプロセスで）同じ parser の版の記録が保存されていれば、それを残す。DB がロックされているなどの読み出しの失敗は「記録なし」と扱わない。
