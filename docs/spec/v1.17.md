# v1.17 追加要件：CLI と MCP の引数の一致

2026-11-20。v1.16 に加える。
根拠は、CLI と MCP の引数の対応の欠けが過去に見つかり（[検証記録](../validation.md) の 2026-10 の節で未対応とした `analyze --detail`、`cache-analysis --batch-offset` など）、その後に手で補ったが、再び食い違っても気づく手段が無かったこと。

1. **MCP のツールには、同じ引数を持つ CLI のサブコマンドがある**：18 のツールのそれぞれに 1 つのサブコマンドが対応する。ツールの引数はすべて CLI から指定でき、CLI の引数はすべてツールの引数に対応する。対応の表は `tests/test_cli_mcp_parity.py` に置く。
2. **名前の違いは、次の決まりに限る**：繰り返し指定する引数は CLI では単数（`--synonym` と `synonyms`）、ファイルで渡す本体は CLI では `input`（`analysis`、`answer`、`translations`）、構造を持つ引数は CLI では個別の引数（`filters` は `--country`、`--source-type`、`--study-design`。`source_preference` は `--prefer-source-type`、`--source-role`、`--source-mode`）、真偽の向きが逆のものは `--no-download` と `download` だけ。このほかの読み替え（`--llm` と `use_llm`、`analyze --refresh` と `force_refresh`、`comparison --study-id` と `selected_study_ids`）は表に明記する。
3. **必須と既定値と選択肢は一致する**：ツールで必須の引数は CLI では位置引数、任意の引数はオプションとする。既定値は同じ値とし、選択肢のある引数は同じ選択肢を持つ。
4. **範囲はコアが検査する**：数値の下限と上限、文字数の上限は、CLI では検査せず、コアが `INVALID_INPUT` で拒否する。MCP のスキーマに書いた範囲は、すべてコアにも同じ検査がある。この版で次を揃えた。
   - `compare_protocols`、`research_protocol`、`cache_protocol_answer` の `question` に、スキーマの上限（2000 字）を加えた（コアは以前から拒否していた）。
   - `cache_protocol_analysis` は、2000 字を超える `question` を、その呼び出しで拒否する（以前は、最後の保存で初めて拒否していた）。
5. **CLI だけのもの**：ツールを持たないサブコマンドは、利用者が端末で実行する保守の操作（`import-csv`、`import-all`、`backfill-protocols`、`merge-observations`、`cleanup-cache`）に限る。`search --all-studies` は、古いコマンド行を受け付けるための非表示の引数で、何もしない。
6. **変えるときは両方を変える**：ツールかサブコマンドに引数を足す、既定値や選択肢を変える、範囲を足すときは、もう一方と表を同じ変更で改める。食い違いは `tests/test_cli_mcp_parity.py` が落ちて知らせる。
